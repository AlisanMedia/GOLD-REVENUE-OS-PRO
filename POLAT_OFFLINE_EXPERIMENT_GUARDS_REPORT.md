## Journal and recovery guarantees

Fresh directory0700, evidence/lock files0600, exclusive create, no symlink following, bounded2MiB/1024 rows, duplicate-key validation before ordinary JSON object materialization, canonical hash chain/sequence, fsync before effect and after result. A normal290-target run needs at most582 header/reservation/result/stop rows. Independent real Node processes cannot share one writer lease. File identity/size drift, truncation, missing journal, duplicate JSON keys, changed hashes and incomplete lines fail closed rather than silently reset counters. No update/delete API exists.

A persisted reservation without a terminal result is `UNSETTLED_ATTEMPT`, requiring review; no automatic lock stealing or blind retry. A completed response lost to its caller remains replay-safe but cannot be recovered as text from a hash. Real recovery must retain the original journal and independently reconcile missing output/billing. A crashed process can leave a lock; an operator must establish it is no longer active before any separately reviewed recovery. Do not create a fresh directory to evade an unsettled run.

This local journal is not WORM storage, a cross-host database, a global account meter, a genuine receipt ledger or authentication. A local owner who rewrites all files/hashes can defeat integrity-only evidence. Future genuine acceptance requires authenticated owner/release authority, a server-owned single-run/journal location, durable evidence custody across runner restarts and independently enforced account limits. An ephemeral Vercel filesystem or a recreated CI directory is not such a store. No hosted persistence is added here.

Journal fields contain hashes, counters, safe durations and labelled synthetic cost/QA outcomes, not raw prompts/replies, customer identifiers, credentials or errors. Returned model observations reuse the accepted contract and remain SYNTHETIC/financial authority NONE; completion remains NOT_COMPLETED, not delivery. The journal is Linux/pinned Node24 tooling, not a newly deployed Admin screen.
