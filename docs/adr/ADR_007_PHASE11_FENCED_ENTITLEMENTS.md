# ADR 007 — Fenced subscriptions and Telegram access

Status: ACCEPTED — Phase 11 formally CLOSED for fenced subscriptions, sandbox access and isolated real-Telegram private-staging acceptance, explicitly owner-approved on 2026-10-16. Live payments, production entitlement activation and Phase 12 remain NOT AUTHORIZED.

Reuse the modular monolith, tenant/RBAC checks, commercial versions, payment evidence ledger and transactional PostgreSQL jobs. UTC calendar month/year durations clamp at month end; fixed days are exact UTC days. Renewal extends from max(current expiration, activation); each payment has an immutable period and offer/plan snapshot. Grace defaults to zero and requires explicit approval. Renewal scheduling never charges money or sends reminders automatically.

Live payment evidence is an immutable private receipt bound to the trusted payment.confirmed event, customer, approved commercial offer, authenticated provider signature and independent verification. There is no deployed receipt writer or live activation endpoint. Runtime roles cannot change approval controls or insert receipts. The live consumer defaults closed. Phase 10 simulations remain payment.test_observed and can only create TEST subscriptions in active, outbound-disabled phase11-sandbox tenants. They cannot become AI action receipts or mutate customer PAID state.

Subscription transitions, append-only evidence/audit and access jobs commit atomically. Grant jobs have revision-bound exclusive leases and bounded retry backoff; stale completions cannot revive held/expired/cancelled access. Access authorization checks current entitlement, verified numeric Telegram identity, channel mode, private status and approved scope. Username alone is insufficient. Approval-required expiring invitations avoid transferable unrestricted links; the matching user must be approved and membership independently observed. Hold/expiry cancels invitation authority and queues revocation. Reconciliation detects membership mismatch and requests repair. Existing human takeover and outbound controls are preserved; no new AI tools or autonomous messaging are enabled.

The registered worker uses only the test adapter; it cannot call Telegram. The dormant API adapter requires exact server-owned channel/account allowlists and approval, checks private channel and bot invite/restrict permissions, and uses additional expiring join-request links, approveChatJoinRequest, membership lookup and ban/revoke. At initial implementation, no owner-authorized staging channel/account had been supplied, so real Telegram grant/revoke acceptance was then an owner setup gate. This historical limitation was resolved during the separately restricted Telegram acceptance on 2026-10-16; see `PHASE_11_REPORT.md`. This does not enable the dormant API adapter in the deployed application. No live payment, production VIP or broad rollout is authorized.

The customer status presenter uses backend receipts and one joining action only after authorization. Test previews are labeled; raw invitations/tokens never enter AI context. Existing quality checks receive only scoped, source-bounded LIVE receipt statements. Telegram-native digital purchases retain Stars; external crypto remains independent web only. Live checkout/merchant availability, tax and geographic rules are not invented. No Türkiye acquisition or business-registration assumption is introduced.
